## 5. Long-term hygiene (the universal-platform shape)

These aren't audit findings — they're conventions to settle going forward
so the next audit doesn't see the same drift.

### 5.1 Directory layout

```
<repo>/
  scripts/                  # code, in git
  protocols/                # protocol templates, in git
  config.sh                 # cluster constants, in git
  docs/                     # docs, audit reports, manuals (PDFs gitignored)
    audit/
      mac-mirror-<date>.md  # tracked
      github-<date>.md      # tracked
      cluster-<date>.md     # tracked
      proposal-<date>.md    # tracked
  molecules/<mol>/
    <mol>_clean.pdb         # tracked (input)
    <mol>.xyz               # NOT tracked (generated)
    charge.txt              # NOT tracked (generated by propka_prep)
    propka/                 # NOT tracked (intermediate working files)
    <protocol>/             # NOT tracked (compute artifacts)
    _archive-*/             # NOT tracked, pruned >30 days
```

### 5.2 Sync direction (per audit answer #2)

- Code: GitHub → Mac → Cluster (git pull only on cluster; never edit on cluster)
- Outputs: Cluster → Mac (rsync on demand; cluster is source of truth)
- Audit reports: written wherever they're generated, committed to GitHub

### 5.3 Disk hygiene rules

| Artifact type                | Cluster lifetime                     |
|------------------------------|--------------------------------------|
| `.cosmo` files               | Permanent (deliverable)              |
| Success stamps               | Permanent (tiny)                     |
| mos files from a successful run | Until next regen, or 30 days, whichever sooner |
| mos files from a failed run  | Delete immediately when failure confirmed |
| `_archive-*/` directories    | 30 days, then prune                  |
| `.bak` files in molecule root| Delete after 30 days if not referenced |

### 5.4 Periodic re-audit

`scripts/audit_cluster.sh` is now in the repo. Run quarterly (or when
`du -sh $VSC_DATA/turbomole-cosmo` exceeds some threshold like 50 GB),
commit the report, draft a new proposal. The audit/proposal cycle is
the operational discipline that keeps the platform sustainable.

## 6. Preservation rules (what NEVER gets touched)

For the record, the aggressive cleanup will NOT delete:

- Any `.cosmo` or `.ccf` file (deliverables)
- Any `*_ok*.stamp` file (success records)
- Any active `<mol>.xyz` or `charge.txt`
- Any PDB / SDF input file
- Any tracked file in git
- The `propka/` workdir for any molecule
- The `_archive-*/` directories newer than 30 days
- The running vancomycin OPT job's working directory
- The queued lysozyme xtb SP job's GFN-xTB-OPT/ dir (currently empty)
